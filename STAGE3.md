# STAGE 3 — что делает каждый шаг (простыми словами, по порядку)

Stage 3 — это помощник-бухгалтер внутри OpenCode.
Сам он не считает: он вызывает движок Stage 1 через кнопки-инструменты (MCP), показывает ответы и отдаёт непонятное разработчикам.
Правило: сверка начинается только по просьбе человека, сама ничего не запускает.

## Шаг 0. Действующие лица (за 30 секунд)

- **Агент `Reconcile`** — характер помощника: говорит по-русски, кода не пишет, в файлы не лезет, работает только разрешёнными кнопками.
- **MCP-сервер `finolimp`** — набор из 12 кнопок: снять копию данных, проверить, посчитать, показать итоги, найти строку, передать кейс.
- **Скиллы** — 4 шпаргалки-сценария: месячная сверка, разбор строки, непонятный случай, улучшение правил (последний — только для разработчика).
- **Runtime** — сейф `stage3_ai/.finolimp/runtime/`: копии данных (`datasets/ds-*`), результаты (`runs/run-*`), кейсы (`cases/`). Оригиналы в `stage1_rules/input/` не трогаются.

## Шаг 1. Открыть помощника (`run_ai.py` + `opencode.json`)

Человек запускает `run_ai.py` — открывается OpenCode с папкой `stage3_ai`, где лежит конфиг: агент по умолчанию `reconcile` и локальный MCP-сервер (`uv run python -m finolimp_mcp`, 15 минут на расчёт). При первом использовании — команда `/connect` (подключить провайдера).

> Пример. Конфиг целиком: `{default_agent: "reconcile", mcp: {servers: {finolimp: {command: ["uv","run","python","-m","finolimp_mcp"]}}}}`. Нужны `uv` и Python 3.11+. Из корня проекта эти настройки не грузятся — там обычные Build/Plan.

## Шаг 2. Что агенту можно, а что нельзя (`reconcile.md`)

Сначала всё запрещено, потом точечно разрешено: задавать вопросы, 3 скилла, 10 кнопок, чтение кода Stage 1 и своих отчётов. Запрещено: читать выгрузки (`input/*.csv`) и бинарный Excel, запускать shell, править файлы.

> Пример. Агент может прочитать `../stage1_rules/src/reconcile2.py`, чтобы объяснить «почему такое правило», и обязан дать путь с номерами строк. А попросить «поправь правило» — это уже граница: он предложит режим Build и сам править не станет.

## Шаг 3. Снять копию данных (`register_current_dataset`)

Первая кнопка: копирует 3 выгрузки + настройки в сейф под номером `ds-*`, считает SHA-256 и размер каждого файла. Лишние файлы (например, `unrelated.txt`) игнорируются. Копия замораживается в read-only.

> Пример. `ds-13fb8ea8f23a4f149b6b22cd5ab471ad`: `acts.csv` (3 375 457 байт, sha `8dd0d7c5…`), `etm.csv` (4 616 480 байт), `registry.csv` (2 160 514 байт), `reconcile.yaml` (5 284 байта). Всего таких копий 6.

## Шаг 4. Проверить данные без расчёта (`validate_dataset`)

Вторая кнопка: прогоняет загрузку Stage 1 без сверки и показывает, что внутри: сколько строк, с каких по какие даты, какие технические пометки. Если файл подменили (хеш не сошёлся) — `ready: false`, дальше не пускает.

> Пример. Ответ: `ready: true, acts 19053 / etm 32254 / registry 13310 строк, черновиков 342; даты 2026-01-01 → 2026-07-31`. Агент показывает эти диапазоны человеку и спрашивает согласие гнать полный период — фильтра «только июнь» нет, считается всегда весь снимок.

## Шаг 5. Посчитать (`run_reconciliation`)

Главная кнопка: запускает `match.py` (весь Stage 1) в отдельном процессе до 15 минут, пишет лог `pipeline.log`, строит книги `finolimp_reports.xlsx` + `README.xlsx`, переводит коды проверок на русский, замораживает папку `runs/run-*`. Книги — для удобства, CSV при этом не стираются; если книга не собралась — в отчёте будет `presentation_warning`, а не падение.

> Пример. Хвост лога `run-41757ebc…`: `WROTE bundle → reports: discrepancies, summary, quality, review_candidates, agent_risk, employee_risk, agent_actions, label_map`; `agents: 100 | top old_money: Сатар уулу Санжар 11177911`; `move_etm −8375511.56 | fix_1c 9031615.91 | clarify 67527511.29`. Манифест: `status completed, started 14:57:44 → finished 14:58:25`, 11 отчётов. Всего таких запусков 7.

## Шаг 6. Показать итог (`get_run_summary`)

Кнопка «итог одной картинкой»: сколько расхождений по каждой метке, какие поручения (не проводки!), у кого остаток не ноль, сколько кандидатов и каких типов, какие технические пометки, какие книги лежат рядом.

> Пример. `discrepancy_count 2165 (бот 267, 1С 1022, агент 56, выяснить 820); nonzero_residual [] (пусто — всё замкнулось); manual 87; quality: nospace 959, subset 581, орфаны 481…; available_reports: 9 CSV + finolimp_reports.xlsx + README.xlsx`. Быстрый просмотр готового результата — это `list_runs → последний completed → get_run_summary → стоп`, без вытягивания строк.

## Шаг 7. Найти строки (`list_discrepancies` + `get_discrepancy_detail`)

Поиск по расхождениям с фильтрами (метка, агент, текст) и номерами `dsp-000001…`; детали одной строки: суммы, разница, комментарий, интерпретация по метке и честное ограничение.

> Пример. `list_discrepancies(run, source=1С, agent=Булак, limit=25)` → строки вроде `dsp-000002: Ak-Bulak Voyage, билет 2460733507, 1С 0, ETM 25741, разница −25741`. Детали `dsp-000002`: `source 1С, комментарий «Есть только в ETM (бот)…», interpretation «операция реальна — довнести в 1С», limitation «метка Stage 1, а не подтверждение по первичке»`.

## Шаг 8. Показать очередь и пометки (`list_review_candidates` + `list_quality_findings`)

Отдельно — кандидаты человеку (`cand-000001…`, 87 шт.: войды без ETM-войда 48, FX 20, пропуски актов 19) и технические пометки (`quality-…`, 415 шт.) — всё с русскими названиями и пояснениями «что проверить».

> Пример. Кандидат: `«В реестре есть сторно, но в ETM сторно не найдено… Билет 2460733507, проверить возврат денег»`. Пометка: `«Платёж ETM ссылается на документ другого субагента: txn 57099246, ЦБ-С002174 → владельцы: karakol express»`. Это сигналы, а не ошибки.

## Шаг 9. Непонятное — разработчикам (`submit_case_for_build`)

Если доказательств нет или случай не поддержан: агент собирает у бухгалтера «что случилось + что ожидалось + документы + номер запуска/строки» и кладёт кейс `cases/case-*.json` (статус `submitted`). Пайплайн при этом не меняется, обучения не обещает.

> Пример. `case-<hex>: {description: «…», expected_behavior: «…», run_id: run-41757…, discrepancy: dsp-000042, status: submitted, notice: «пайплайн не изменён»}`. Папка `cases/` сейчас пуста — кейсов ещё не создавали. Посмотреть их можно кнопками `list_build_cases / get_build_case` (это уже для режима Build).

## Шаг 10. Книги и словарь (`excel_reports.py` + `report_dictionary.py`)

Книги строятся только из CSV и CSV не меняют: `finolimp_reports.xlsx` — 9 листов с русскими названиями (`Расхождения, Сводка сверки, Качество данных, Кандидаты на проверку, Действия по субагентам, Риск субагентов, Показатели сотрудников, Признаки расхождений, Карта имён`), числа — числами, ID и билеты — текстом (чтобы Excel не съел нули), `=1+1` — текстом, а не формулой. `README.xlsx` — словарь: тех.поле → русское → пояснение. Если для поля нет описания — книга не строится, смысл не угадывается.

> Пример. Шапка листа: `Субагент | Дата | Билет | Сумма по 1С | Сумма по ETM | Разница | Пояснение | Причина` + колонка `Пояснение проверки`. Словарь: `residual | Контрольный остаток | Конечный разрыв минус объяснённая часть. Ноль подтверждает замыкание, но не правильность сопоставлений`.

## Шаг 11. Скиллы-сценарии (4 шпаргалки)

- **monthly-reconciliation** («Месячная сверка», 7 шагов): дождаться просьбы → копия → проверка → показать даты и проблемы → согласие → расчёт → итог → предложить детали. Настаивает: книга — человеку, анализ — по CSV; `source` — вывод правил; кандидаты — не выводы.
- **discrepancy-review** («Разбор строки»): детали → пересказ сумм и комментария → «почему такая метка» только по коду с путями → что требует первички → нет доказательств → кейс в Build.
- **unsupported-case** («Неподдержанный случай»): собрать факты → `submit_case_for_build` согласованным текстом → «кейс создан», без обещаний и секретов.
- **pipeline-improvement** (только Build): взять `case_id` → требование и границы → отдельная ветка → правка + тест → профильные тесты и баланс → описание человеку.

## Шаг 12. Безопасность сейфа

Копии и запуски неизменяемы: хеши перепроверяются, подмена → `ready: false` / новый снимок; права POSIX `0700→0500` (папки) и `0600→0400` (файлы); пути наружу запрещены (защита от `..`); входов с путями/shell/SQL у кнопок нет.

> Пример. Попытка подсунуть чужой `dataset_id` вида `../../etc` — отклоняется проверкой формата `^ds-[0-9a-f]{32}$`. Несуществующий запуск — ошибка, а не пустой ответ.
