# Сверка 1С и ETM — stage1_rules (rule-based движок)

Порт инструмента из `first_step` на данные финала: 100 субагентов, 7 месяцев (янв–июл 2026),
плюс реестр агентов как подсказка об источнике расхождения. Только детерминированные
правила, ноль обучаемых параметров: каждая строка выхода прослеживается до правила
и входных строк. Папка содержит только движок, его конфиг, входы, тесты и этот README.

Состав папки: `reconcile2.py` (движок), `parse.py` (общий парсинг/загрузка —
единая точка правок для движка и матчера, см. шапку файла), `reconcile.yaml` (все правила),
`acts.csv` / `etm.csv` / `registry.csv` (входы), `tests/test_reconcile2.py` (36 тестов).

## Запуск

Требуется Python 3, `pandas`, `pyyaml` (без последнего — встроенные дефолты).

```bash
python3 reconcile2.py
```

Скрипт читает лежащие рядом `acts.csv`, `etm.csv`, `registry.csv` и создаёт:

- `discrepancies.csv` — 2165 строк:
  `agent,date,identifier,sum_1c,sum_etm,diff,comment,source`, где `diff = sum_1c − sum_etm`,
  ETM в знаке 1С (списание положительное); `source` — Шаг 4 (где ошибка):
  `бот` 267 (пропуск/дубль/EТМ-занижение при реестре≈1С — v3 R1; дубль
  платежа — v3 R3b), `1С` 1022 (операция реальна по ETM+реестру, в учёте нет;
  +одиночные ETM-платежи — v3 R3a), `агент` 56 (реестр≈ETM≠1С — бот скопировал
  добросовестно, ошибка в учёте агента; v3 RA, якоря S110/S117/S119/S122),
  `выяснить` 820 (требует первички/лаг/сторно/синглтоны);
- `reconciliation_summary.csv` — проверка увязки по каждому из 100 агентов
  (+ `ignored_draft_rows`, `one_sided`, `alias_of`);
- `quality_report.csv` — инвентарь технических и данных проверок (количество зависит от выгрузки).
- `agent_actions.csv` — поручения на субагента (Шаг 6): `move_etm_by` / `fix_1c_by` /
  `clarify_money`+`clarify_n`; `move_etm_by` и `fix_1c_by` — изменения баланса/сальдо
  (плюс увеличивает, минус уменьшает); тождество с `operation_diff` сходится в ноль (100/100).
- `employee_risk.csv` строит suspect-rate по всем строкам реестра сотрудника, а не только
  по строкам, попавшим в список расхождений.
- `review_candidates.csv` — отдельные типизированные кандидаты для ручного аудита
  (`missing_act_block`, `registry_void_without_etm_void`, `possible_fx_difference`).
  Они не меняют `discrepancies.csv`/`source` и не трактуются как готовая атрибуция.

Пути переопределяются параметрами `--acts`, `--etm`, `--registry`, `--output`, `--summary`,
`--quality`, `--review-candidates`, плюс `--config` (по умолчанию `reconcile.yaml`
рядом). Повторный запуск из тех же файлов даёт байт-в-байт те же выходы.

## Методика (ядро)

- Суммы: `sum_1c = debet − credit`, `sum_etm = −amount_kgs`. Деньги чистятся
  централизованно в загрузчике (`1 234,56`, `$`, `(скобки)`, `н/д` → число/NaN+флаг).
- Билеты: ключ — последние 10 цифр, дефисы/коды авиакомпаний отбрасываются.
- Билетные строки сопоставляются связными компонентами по общим номерам (many-to-many).
  Компонента выводится как расхождение, если разница превышает копейку.
- Платежи (пустой билет): фаза 1 — точный мэтч сумма+номер `ЦБ-С` из комментария ETM
  (1076 из 2199 несут ссылку), фаза 2 — сумма внутри `date_window_days` (дефолт 120),
  ничья — ближайшая дата. Несовпавшие выводятся отдельно.
- `act_status`: `переиздан` вытесняет `черновик` в рамках папка+период
  (342 строки → `ignored_draft_rows`).
- Проверка сальдо: `конечный разрыв = начальный + межпериодный + сумма расхождений
  + residual`, разрыв = `сальдо 1С + баланс ETM`. Итог: **100/100, `residual = 0`**.
  Оговорка: residual доказывает замкнутость арифметики, корректность мэтчинга —
  golden-тесты и инварианты ниже.

## Конфиг (`reconcile.yaml`)

Все правила — здесь, новая ситуация правится без кода: `tolerance`, `stopwords`,
`status_policy`, окно платежей, валюты/курсы (`amount × курс(date)` при отсутствии
`amount_kgs`; курсы из реестра, иначе `fallback_rates`), `agents.aliases`
(переименования, цепочки разрешаются), `labels.source`, `dates.*`, `void_kinds`,
`sale_kinds`, `v3.*` (`data_end: auto` = max дата выгрузок — новый месяц без правок). Неизвестный ключ/неверный тип — `WARNING` + дефолт, скрипт не падает
(контракт данных — отсутствие колонок, нечитаемый файл — явная ошибка с текстом).

## Слой имён: деньги строго, реестр — с авто-мёржем

- Акты↔ETM: только `exact+alias`. Ложное слияние хуже ложного разделения.
- Реестр клеится сам (`auto_merge`): `exact → nospace → homoglyph (11 пар) →
  строгий fuzzy (ratio ≥ 0.94 И общие билеты И однозначность) → v2 subset
  (короткое имя партии — token-подмножество ровно одного агента И общие билеты)`;
  иначе — предложение человеку (`possible_duplicate_agents` → строка в `aliases`).
  Каждый нестрогий шаг — в quality. Эффект: 959 строк вернулись nospace-слиянием,
  581 — subset-слиянием (v2), орфаны 2021→1062→481; 58 строк — двоякие
  (`ambiguous_subset`, не мёрджим). Остаток 481 полностью разобран в `ORPHANS.md`
  (Q3: 6 чужих партий без пересечений + «Джолдош уулу» между двумя агентами —
  aliases не добавлялись осознанно).
- Подпись агента — единый хелпер `canonical_labels` (`acts_first` по дефолту).
- Суммы реестра в KGS (`parse_pay_kgs_total`, Q2): все валюты через курсы строки
  (якоря S110/S112/S119; курсы округлены — сравнение с CONV_TOL 2.0).
- v3-микрорулы атрибуции (Q1, секция `v3` конфига, `enabled=false` = режим v2):
  R1 (реестр≈1С + только бот + одна строка реестра + |diff|>500 + не свежая → бот,
  107 сраб.), R3a/R3b (старые ETM-платежи: близнец ≤7д → бот-дубль, 24;
  иначе → 1С, 77), RA (реестр≈ETM≠1С + только бот + одна строка + diff>500 +
  diff>0 + не свежая → агент, 56 сраб.; S100-штраф отсечён однострочностью).
  Экзамен на 130 ручных ошибках: 125/130 lenient (exact-side: 109/114
  атрибутируемых + 16 структурных «—»); остаток: S100/S106/S141 (R4/R5,
  осознанно) + S112/S116 (класс плоских тысяч при реестре==1С).

`unknown_status/kind/creator/currency`, `unparseable_date/money`, `nonstandard_encoding`,
