## 0. Паспорт проекта (слайд 1–2)

**Бизнес-задача.** Субагенты продают авиабилеты. Три источника правды расходятся:

- **1С (`acts.csv`)** — бухгалтерия: что проведено в учёте по папкам-субагентам, помесячными актами с сальдо.
- **ETM (`etm.csv`)** — операционный журнал: выкупы/оплаты/возвраты/войды, баланс после каждой операции, автор (`etm-bot` — загрузочный бот, `субагент` — самовыписка).
- **Реестр (`registry.csv`)** — ручной учёт агентов: кто, когда, кому, по каким билетам, сколько денег (`pay_cell` в произвольных валютах + курсы строки). Это «улика» об источнике ошибки, а не деньги движка.

**Вопрос проекта:** по каждому субагенту — где ошибка: **бот** (не загрузил/задвоил/занизил ETM), **1С** (операция реальна, в учёте нет), **агент** (ошибка в учёте агента, бот скопировал добросовестно), **выяснить** (нужна первичка: комиссии, лаги, сторно, синглтоны). Плюс: сколько двигать балансы, кого обходить первым, что отдать человеку на ручную проверку.

**Архитектура — 3 Stage с жёсткой границей:**

| Stage | Что | Технология | Статус результата |
|---|---|---|---|
| **Stage 1 — правила** (`stage1_rules/`) | Детерминированный rule-based движок: билеты компонентами, платежи в 2 фазы, атрибуция `source`, увязка сальдо, очередь `review_candidates`, признаки, ранги, поручения | Python + `pandas` + `pyyaml`, ноль обучаемых параметров | **Бухгалтерский эталон.** Единственное основание для проводок |
| **Stage 2 — ML-второе мнение** (`stage2_ml/`) | Run-local ML: 4 классификатора (status / ticket-пары / payment-пары / source), обучение только на ранних датах, validation на поздних, метки — silver от Stage 1 | `scikit-learn` `HistGradientBoostingClassifier` (+ `Dummy` fallback) | **Независимой проверкой не является.** Только fidelity к Stage 1 out-of-time |
| **Stage 3 — AI-агент** (`stage3_ai/`) | Агент `Reconcile` в OpenCode + локальный MCP-сервер: snapshot входов, валидация, запуск Stage 1 bundle в subprocess, чтение отчётов, Excel-книги, передача кейсов в Build | OpenCode + `FastMCP` (stdio), `openpyxl` | Тонкий слой над Stage 1, логики сверки не содержит |

**Правило границы (критично для презентации):** Stage 2 никогда не правит файлы Stage 1 — только читает. Stage 1 не знает про Stage 2 (ноль импортов в ту сторону). `review_candidates` никогда не меняют `source`. ML-результат не заменяет поручения Stage 1. Train-метки Stage 2 — производные от текущего Stage 1 («silver»), это самообучение/второе мнение, а не независимая проверка качества правил.

**Оркестратор всего:** `run_stage_1_2.py` (Stage 1+2), `run_ai.py` (открыть OpenCode в `stage3_ai/`). Каждый запуск пишет **новую** папку `.finolimp/manual_runs/<run-id>/` с `stage1/`, `stage2/`, `manifest.json`; существующие результаты не перезаписываются. На POSIX завершённая папка замораживается в read-only owner-only (`0500` каталоги / `0400` файлы).

## 2. Конфиг `reconcile.yaml` — все правила построчно (как написать с нуля)

Философия `never-fail`: неизвестный ключ — `WARNING + ignore`, неверный тип — `WARNING + default`, скрипт не падает. Контракт данных (нет колонок, нечитаемый файл) — явная ошибка с текстом. Дефолты в коде (`parse.DEFAULT_CONFIG`) = поведение v1.

1. **`tolerance: 0.01`** — всё, что меньше копейки, сошлось. Все сравнения сумм идут через `|a − b| < tol`.
2. **`input.encodings: [utf-8-sig, utf-8, cp1251]`** — порядок перебора кодировок в `read_csv_smart`. `strip_strings: true` — `strip()` всем строковым клеткам, `"" → NA`. `date_formats: [%Y-%m-%d, %Y-%m-%d %H:%M:%S, %d.%m.%Y, %d.%m.%Y %H:%M:%S, %d/%m/%Y, %Y/%m/%d]` — порядок попыток `pd.to_datetime(format=fmt)`, остаток — свободный парсер. `thousands_separators: [" ", " ", "'", "’"]` — вырезаются из денег (`1 234,56`, `1'234.56`).
3. **`names.stopwords: [осоо, ooo, ocoo, ип, зао, oao, оао, llc, ltd, гп, чп, чуп]`** — вырезаются по границам слов в `norm_agent`. `homoglyphs: {a→а, e→е, o→о, p→р, c→с, x→х, m→м, k→к, t→т, b→в, h→н}` (11 пар — самая частая «опечатка в 1 символ»). `fuzzy_suggest_threshold: 0.90` (подсказка человеку), `fuzzy_auto_threshold: 0.94` (автомёрж только если score ≥ 0.94 **И** общие билеты **И** однозначность). `auto_merge: true`, `subset_auto_merge: true`, `enabled: true` (`false` = режим v1 только exact+alias).
4. **`status_policy: reissued_markers: [переиздан], drop_if_reissued: [черновик], always_drop: []`** — `переиздан` вытесняет `черновик` в рамках `папка + период` → 342 строки уходят в `ignored_draft_rows`.
5. **`tickets: {min_digits: 10, tail: 10}`** — ключ билета = последние 10 цифр (`re.findall(r"\d+")`, хвосты `d[-10:]`, если `len(d) ≥ 10`). Дефисы/коды авиакомпаний отбрасываются (`604-2461882546` → хвост; 13-знак ETM стыкуется с 10-знаком 1С). Короче 10 цифр = мусор в quality (`short_ticket_number`).
6. **`payments: {date_window_days: 120, review_gap_days: 45, prefer_doc_match: true, doc_pattern: 'ЦБ-С\d+'}`** — окно жадного матч
а платежей 120 дней; гэп > 45 дней — `long_gap_payment` в quality; сначала точный `ЦБ-С`, потом greedy по сумме.
7. **`void_kinds: [войд, void]`, `sale_kinds: [выкуп]`** — словари видов для войд-проверок.
8. **`dates: {normalize_tz: true, range_margin_days: 15, edge_days: 45, check_balance_chain: true, balance_tolerance: 0.01}`** — снять часовые пояса (стенное время); даты вне `[min_period − 15д, max_period_end + 15д]` — `date_out_of_range`; войд раньше продажи в пределах 45 дней — `window_edge`, дальше — `alarm`.
9. **`currencies: {base: KGS, resolved_column: amount_kgs, amount_column: amount, currency_column: currency, rate_columns: {USD: rate_usd, EUR: rate_eur, RUB: rate_rub, KZT: rate_kzt}, fallback_rates: {}}`** — legacy-путь: если `amount_kgs` вся непуста → `sum_etm = −amount_kgs`; иначе `amount × курс(валюта, дата)` (последний курс на/до даты, иначе первый доступный, иначе fallback, иначе `unknown_currency` + пропуск).
10. **`agents.aliases: {}`** — переименования (`{"Старое ОсОО": "Новое ОсОО"}`), сверка по норме, цепочки разрешаются с защитой от цикла.
11. **`labels.source: acts_first`** (альтернатива `most_frequent`) — подпись агента в отчётах: приоритет 1С, fallback ETM.
12. **`comments.void_remainder_note: false`** — отдельный диагноз войда с остатком (выкл.).
13. **`v3: {enabled: true, conv_tol: 2.0, r1_min_diff: 500.0, ra_min_diff: 500.0, twin_window_days: 7, data_end: auto (= max дат acts+etm), fresh_days: 31}`** — микрорулы атрибуции (см. 4.4): `conv_tol` — допуск сравнения с реестром через курсы (курсы округлены до 2 знаков); пороги 500 сом (мелочь < 200 не трогаем); близнец платежа ≤ 7 дней; свежее 31 дня = лаг, не ошибка (щит).
14. **`output.quality_report: quality_report.csv`**.

## 4. STAGE 1 — правила: каждый файл пошагово

Порядок чтения/исполнения: `io_clean.py → parse.py → reconcile2.py → review_candidates.py → match.py → build_features.py → rank.py → build_actions.py → sample_adjudication.py (one-off)`.

### 4.1. `src/io_clean.py` (168 строк) — чистая механика ввода, без решений

Единственный модуль Stage 1, разрешённый на inference Stage 2 (вместе с сырыми CSV и frozen `train/`). Сюда вынесено 1-в-1 из `parse.py` без изменения логики. Ноль норм имён, алиасов, мёрджей, матчинга, атрибуции, курсов.

- `TICKETS_DEFAULT = {"min_digits": 10, "tail": 10}` — единственный источник (переиспользуется в `parse.DEFAULT_CONFIG["tickets"]`).
- `class QualityLog`: `__init__` (`_rows`, `_seen_keys`); `add(check, key, count=1, sample="", dedup=False)` — append `{check, key, count, sample[:200]}`, при `dedup=True` повтор `(check,key)` игнорируется; `summary() → {check: Σcount}`; `to_frame() → DataFrame[check,key,count,sample]`, сортированный по `check,key`.
- `read_csv_smart(path, cfg) → (DataFrame, encoding)` — перебор `input.encodings`; `UnicodeDecodeError → следующая`; пустой файл → `ValueError("пустой файл без шапки")`.
- `strip_string_cells(frame)` — `strip()` всем object-клеткам; `"" → NA`.
- `parse_money_value(value, seps) → float` — одна сумма: числа прозрачно; строки: вырезать `seps`, `(скобки) = отрицательное`, вычистить всё кроме `0-9,.-`, учесть позицию последнего `,`/`.` (`1 234,56`); неуспех → `NaN`.
- `parse_money_series(series, cfg, qlog, colname)` — числовые → `astype(float)`; иначе `map(parse_money_value)`; прирост `NaN` → `qlog.add("unparseable_money", colname, bad, пример, dedup=True)`.
- `strip_timezone(series, cfg, qlog, colname)` — снять часовые пояса (стенное время), иначе naive/aware дадут `TypeError`; при наличии зоны — `qlog.add("tz_normalized", …)`.
- `parse_date_series(series, cfg, qlog, colname) → datetime64` — поочерёдно `pd.to_datetime(format=fmt)` по `date_formats` (каждую попытку через `strip_timezone`), остаток — свободный парсер `utc=True`, остаток — `qlog.add("unparseable_date", …)`, вернуть `NaT` там.
- `ticket_numbers(value, cfg) → set[str]` — `{d[-tail:] for d in re.findall(r"\d+", str(value)) if len(d) ≥ min_digits}`; `NaN → set()`.

### 4.2. `src/parse.py` (768 строк) — общий модуль правил поверх `io_clean`

Владельцы: движок `reconcile2.py` и offline-разметка Stage 2. На inference Stage 2 — **запрещён**. Правило разработки: любая правка аффектит обоих потребителей → после правки прогнать (1) `python3 reconcile2.py` + сверка golden-md5 + `pytest tests/ -q`, (2) matcher `reproduce.py + diff_discrepancies.py` + сверка цифр с `EVAL.md`.

### 6.1. `src/matcher/temporal_split.py` — единый хронологический сплит

- `select_cutoff(date_values, validation_fraction = 0.2) → Timestamp`: `to_datetime(coerce).dropna().normalize().unique().sort()`; требует ≥ 2 дат; `split_at = floor(N × (1 − fraction))`, клиппинг `[1, N−1]`; возврат `unique[split_at]`. При 0.2 последние 20% уникальных дат — validation (`≥ cutoff`), ранние (`< cutoff`) — train.
- `date_masks(date_values, cutoff) → (train, validation, unknown)`: `train = date < cutoff`, `validation = date ≥ cutoff`, `unknown = isna`.
- `pair_masks(frame, cutoff) → (train, validation, excluded)`: `train = a < cutoff ∧ e < cutoff`, `validation = a ≥ cutoff ∧ e ≥ cutoff`, иначе **excluded**. Кросс-периодные и undated пары исключаются из обоих фолдов — защита от leakage.

### 6.2. `src/matcher/s2_features.py` — inference-safe парные признаки + union-find

Зависит только от raw-колонок пары + механического `io_clean.ticket_numbers`. Без Stage 1 identity. `toks(text)` — токены `[A-ZА-Я0-9]{2,}` в верхнем регистре; `doc_toks(text)` — докум.-токены вида `ЦБ-С\d+`. `ticket_features(df) → 12 колонок (fillna(−1))`: `tail_any` (общий 10-digit tail), `tail_frac = |∩|/max(1,|∪|)`, `amt_diff = |a − e|`, `amt_eq = (amt_diff < 0.01)`, `date_gap = |a_date − e_date| в днях (−1 если NaT)`, `same_agent_raw` (строковое равенство raw имён, без алиасов), `ek_выкуп/ek_возврат/ek_войд/ek_оплата` (one-hot `e_kind`), `text_jac` (Jaccard токенов `a_text/doc` vs `e_text/comment`), `n_a_tickets` (count `|` + 1). `pay_features(df) → 7`: `amt_diff/amt_eq/date_gap/same_agent_raw/text_jac` + `doc_any` (общий `ЦБ-С`). `union_find(n, edges)` — DSU с path-halving (сборка ticket-кластеров из accepted рёбер и threshold-sweep в evaluate).

## 8. Сквозные сценарии (слайд «Как пользуется бухгалтер»)

**Установка на чистый компьютер (один раз):** Windows `powershell -ExecutionPolicy Bypass -File .\install_windows.ps1`; Ubuntu `bash install_ubuntu.sh` (нужен `sudo` для `apt`). Ставит Python 3.12, создаёт `.venv`, ставит зависимости Stage 1/2 (`requirements-runner.txt`: `numpy ≥ 1.26 < 3, pandas ≥ 2.2 < 4, PyYAML ≥ 6 < 7, scikit-learn ≥ 1.5 < 2, openpyxl ≥ 3.1 < 4`; CatBoost и research-бенчмарки не нужны), готовит отдельное заблокированное окружение MCP, ставит OpenCode CLI. Запуск из корня: Windows `.\.venv\Scripts\python.exe .\run_stage_1_2.py` + `.\.venv\Scripts\python.exe .\run_ai.py`; Ubuntu `.venv/bin/python run_stage_1_2.py` + `.venv/bin/python run_ai.py`.

**Раз в месяц (rollover):** положить свежие `acts/etm/registry.csv` в новую папку → `python3 match.py --input <папка> --out report_<месяц>/` (или `run_stage_1_2.py` из корня). Ничего в настройках менять не надо: `data_end = auto = max дат`. Проверка живости: все `residual` в summary — 0; `pytest tests/ -q` — зелёный на синтетике (md5-гейты на новых данных покраснеют — нормально). Частичная выгрузка: зафиксировать `v3.data_end: "2026-08-31"` в копии yaml + `--config`.

**Только правила:** `run_stage_1_2.py --stage1-only`. **Stage 2 отдельно:** `run_stage_1_2.py --stage2-only --stage1-reports <путь-к-stage1>`. **Доля validation:** `--validation-fraction 0.25`.

**AI-сверка:** `run_ai.py` → OpenCode в `stage3_ai` → `/connect` (первый раз) → просьба в чате → `register → validate → run → summary → детали → кейс в Build`. Нужны `uv` + Python 3.11+. Загрузка файлов через чат, запуск отдельных шагов, рабочая копия Build, одобрение/публикация — не реализованы.

**Как читать `source` (шпаргалка на слайд):** бот — чинить загрузку, строку сверить; 1С — довнести в 1С; агент — спрашивать агента; выяснить — смотреть первичку (подвид: продажа + сторно на следующий день — сначала валидность сторно). Правила обхода: свежие (≤ 31 дня) — лаг, сначала старые; круглые разницы (1000/9000/10000, ровно 5%/10%) — в первичку; самовыписки — спрашивать субагента + довносить в 1С; `residual ≠ 0` — смотреть quality, звать автора; войды — `void_partial_refund` разбирать первым (сейчас 0).
