# FinOlimp MCP для OpenCode

Первая интеграция предоставляет Reconcile-агенту ограниченный набор инструментов
поверх существующего движка Stage 1. Расчётная логика остаётся в `stage1_rules/`;
MCP только проверяет snapshot, запускает `match.py` отдельным процессом, сохраняет
артефакты в новых каталогах запусков и возвращает ограниченные выдержки из отчётов.

## Запуск

Нужны Python 3.11+ и `uv`. Запускай OpenCode из каталога `stage3_ai/`: его
`.opencode/opencode.json` задаёт Reconcile по умолчанию и запускает MCP из
`integrations/finolimp_mcp/`. Из корня проекта FinOlimp этот агент и MCP не
подключаются. Первый запуск `uv run` создаёт окружение по этому `pyproject.toml` и
устанавливает MCP, pandas, PyYAML и openpyxl. Запуск локальный, через MCP stdio; отдельный
HTTP-сервер не нужен.

```bash
cd stage3_ai
opencode
```

Reconcile также имеет read-only-доступ к Stage 1 Python-коду, тестам,
документации, `reconcile.yaml` и отчётам. Отчёты конкретного запуска доступны в
`.finolimp/runtime/runs/<run_id>/reports/`; перед чтением агент проверяет через
MCP, что запуск завершён. Исходные CSV (`acts.csv`, `etm.csv`, `registry.csv`)
запрещены правилами доступа. Shell и редактирование файлов запрещены; для изменений
кода переключайся в Build. Чтобы читать Stage 1 из `stage3_ai`, Reconcile использует
соседнюю папку по относительному пути `../stage1_rules/...`.

Каждый новый завершённый запуск дополнительно получает
`reports/finolimp_reports.xlsx`: каждый CSV-отчёт этого запуска вынесен на
отдельный лист с русским названием и русскими заголовками колонок. В книге качества
данных и в списке кандидатов на проверку дополнительно показаны русские расшифровки
машинных кодов. Числа доступны как ячейки Excel, идентификаторы остаются текстом.
Ширина столбцов заранее рассчитывается по содержимому, а длинный текст переносится.
Заголовки CSV и остальные значения не меняются; значения кодов в `check` и `issue`
в отчётах запуска заменяются русскими пояснениями. Исходные отчёты Stage 1
сохраняются без изменений, а MCP преобразует пояснения обратно во внутренние коды.
Stage 2/ML-отчёты из статической папки в эту книгу не подмешиваются.
Также создаётся `reports/README.xlsx`: у каждого CSV свой лист, а каждая строка
листа содержит техническое имя поля, его русское название и проверенное описание.
Названия листов и пояснения — на русском. Если в отчёте появится неописанное поле, книга словаря не
будет создана вместо того, чтобы угадывать его смысл.
Книга предназначена для просмотра в Excel: встроенный файловый `read` OpenCode
не поддерживает бинарный XLSX, поэтому Reconcile для анализа использует CSV/MCP.
Путь к Stage 1 в инструкциях Reconcile задан относительно `stage3_ai` как
`../stage1_rules/`, без привязки к имени пользователя или абсолютному пути.
Существующие завершённые запуски не переписываются и автоматически не пересчитываются.

Для разработки и тестов:

```bash
cd stage3_ai/integrations/finolimp_mcp
uv sync --group dev
uv run pytest -q
```

## Предоставленные инструменты

- `register_current_dataset`: копирует фиксированный allowlist файлов из
  `stage1_rules/input/` в неизменяемый snapshot.
- `validate_dataset`: валидирует данные тем же `parse.load_data`, что использует
  Stage 1.
- `run_reconciliation`: запускает полный утверждённый bundle в дочернем процессе;
  каждый запуск получает новую папку и дополнительную Excel-книгу из CSV-отчётов.
- `list_runs`, `get_run_summary`, `list_discrepancies`, `get_discrepancy_detail`,
  `list_review_candidates`: показывают безопасные выборки из готовых отчётов.
- `submit_case_for_build`, `list_build_cases`, `get_build_case`: сохраняют передачу
  неподдержанного случая. Передача не меняет и не публикует пайплайн.

Все runtime-данные хранятся в `stage3_ai/.finolimp/runtime/` и исключены из Git. Tool inputs
не принимают произвольные пути, shell-команды или SQL. Оригинальные входы не
перезаписываются; snapshots и завершённые запуски становятся read-only. На POSIX
каталоги доступны владельцу процесса (`0700` до фиксации, `0500` после), файлы —
только владельцу (`0600` при записи, `0400` после фиксации). Перед сверкой hashes
snapshot перепроверяются.

## Граница текущего среза

Пока поддержан полный запуск Stage 1, а не отдельные шаги; вход — существующая
папка `stage1_rules/input/`, а не загрузка файлов через UI. Нет инструмента для
сохранения бухгалтерского решения, изолированной Build-рабочей копии, одобрения
или публикации версии. Поэтому Build может готовить изменение в отдельной ветке/
рабочей копии по обычному процессу, но не должен автоматически обновлять рабочий
пайплайн. Эти функции добавляются следующим вертикальным срезом с проверкой прав
и аудиторским журналом.
